# Архитектура системы

## Контекст
Платформа предназначена для демонстрации полного CASE pipeline: загрузка требований, структурирование, подтверждение человеком, генерация кода, генерация тестов, локальный контейнерный deploy, интеграция с MCP и агентным оркестратором.

## Контейнерная схема
- `frontend` на React/Vite предоставляет операторский UI.
- `backend` на FastAPI реализует API, orchestration, storage и MCP surface.
- `worker` на Celery готов к выносу фоновых задач.
- `postgres` хранит метаданные проектов и запусков.
- `redis` используется Celery и может быть использован для очередей/кэша.
- `nginx` публикует frontend и проксирует API.

## Основные модули
- `providers`: единый слой LLM adapters.
- `services`: CASE workflow и прикладная логика.
- `mcp`: registry, встроенные demo servers и публикация платформы как MCP server.
- `agents`: профили агентов, execution, handoff и память.
- `infrastructure/storage`: файловое хранилище версионируемых артефактов.
- `api`: HTTP-интерфейс для UI и внешних клиентов.

## Основной CASE pipeline
1. Пользователь создаёт проект.
2. Загружает текст требований.
3. Запускает анализ требований и получает JSON + Markdown структуру.
4. Подтверждает или редактирует структуру.
5. Запускает генерацию кода.
6. Запускает генерацию тестов.
7. Запускает dry-run deploy или реальный локальный deploy.

## Разделение LLM adapter и MCP layer
- LLM adapters отвечают только за генерацию текста, структуры, кода и тестов.
- MCP layer отвечает только за внешние tools/resources/prompts и публикацию самой платформы.
- Агентный слой использует оба слоя как зависимости, но не смешивает их ответственность.

## Human-in-the-loop
- Перед подтверждением структуры требований требуется явное `approved=true`.
- Перед генерацией кода и тестов требуется подтверждение.
- Перед deploy требуется подтверждение.
- Для side-effect MCP tools поддерживается approval flow.

## Причины выбора архитектуры
- Для MVP выбран монолитный backend с чёткими слоями вместо микроcервисов.
- Demo mode делает систему воспроизводимой без внешних ключей.
- Хранение артефактов на локальном диске ускоряет демонстрацию и не требует object storage.
- PostgreSQL и Redis уже заложены под следующий этап масштабирования.
